# PcLinkBridge 使用说明

步步高学习机运行 **PCLINK.CMD**（清华大学 唐瑞春，1997），可以通过两台机器并口之间的连线，把 PC
上的磁盘当作一个驱动器使用。PC 端原来运行 **PCSVER.EXE**，这是一个 16 位 DOS 程序，直接读写打印口的
引脚。现在的 Windows 都不允许程序这样做，USB 转并口线也做不到。

PcLinkBridge 用一块 5 V 单片机板（Arduino Uno 或 Nano）通过 USB 代替 PC 的打印口：

    学习机 ──联机线──> DB25 母座 ── Arduino ──USB──> PC：PcLinkServer.exe ── 一个文件夹

还带有真正并口的 PC 可以不用 Arduino，见下面的“不用 Arduino：真正的并口”。

- `firmware/PcLinkBridge/`：Arduino 程序。它在联机线上做 4 位握手，做法与 PCSVER 完全相同，再通过
  USB 串口转发字节。
- `server/`：**PcLinkServer.exe**，用 PC 上的一个文件夹回答 PCLINK 的请求。它直接用模拟器自己的联机
  服务端代码（`Core/NES/Mappers/Bbk/BbkPcLink.h`，已在 MesenCE 里用 PCLINK 验证过）编译而成。
- `test/sim.cpp`：模拟测试。服务端和运行 PCLINK 收发例程的学习机通过模拟的连线通信，服务端一侧先是
  模拟串口上的单片机程序，再是模拟的并口。

> **还没有在真机上试过。** 两种方式都经过模拟测试，Arduino 程序可以编译；第一次真机测试见下面的“试用”。

## 材料

- Arduino **Uno**、**Nano** 或 **Pro Mini（5 V）**（ATmega328P，5 V）。其他 5 V 板子也能用，只是稍慢。
  3.3 V 的板子（Pico、ESP32）十根线都要加电平转换。
- 一个 **DB25 母座**（转接板，或母座加导线），插联机线的 PC 端。
- 十个 **330 Ω** 电阻，每根信号线串一个。接错线时可以保护两端。
- 原来配 PCSVER 用的联机线。这是 LapLink 式的线：每一端的数据脚 2-6 接到另一端的状态脚
  15、13、12、10、11。

## 接线

Arduino 代替 PC 的打印口：

| DB25 脚 | PC 打印口信号 | Arduino | 内容 |
| --- | --- | --- | --- |
| 2 | D0 | D2 | 我方半字节 位 0 |
| 3 | D1 | D3 | 位 1 |
| 4 | D2 | D4 | 位 2 |
| 5 | D3 | D5 | 位 3 |
| 6 | D4 | D6 | 我方握手 |
| 15 | Error (S3) | A0 | 学习机半字节 位 0 |
| 13 | Select (S4) | A1 | 位 1 |
| 12 | Paper out (S5) | A2 | 位 2 |
| 10 | Ack (S6) | A3 | 位 3 |
| 11 | Busy (S7) | A4 | 学习机握手 |
| 18-25 | 地 | GND | |

DB25 的其他脚不接。把联机线接到 Arduino 之前，先用万用表量一下：联机线插在学习机上、PCLINK 装好并
空闲时，联机线 PC 端插头的 15、13、12、10 脚对 25 脚应为约 5 V，11 脚约 0 V（PCLINK 启动时向并口写
$0F：半字节为高，握手为低）。本程序按 5 V 逻辑设计，和 PC 的打印口一样。

## 烧写 Arduino 程序

用 Arduino IDE 打开 `firmware/PcLinkBridge/PcLinkBridge.ino`，选好板子（旧 bootloader 的 Nano 选
*ATmega328P (Old Bootloader)*），点“上传”。

## 运行服务端

用 `build.bat` 编译（需要 Visual Studio C++ 工具），或直接用编好的 `PcLinkServer.exe`：

    PcLinkServer.exe [文件夹] [--port COMn] [--baud n]

- `文件夹`：学习机上的 C: 盘。默认是当前目录下的 `BbkPcLink`，不存在就新建。
- 不给 `--port` 时，逐个尝试所有串口，直到有一个回应。
- `--baud` 必须与 Arduino 程序里的 `BAUD` 相同（默认都是 1000000）。

每个文件操作（open、create、close、dir、cd、md、rd、delete、rename）打印一行。按 Ctrl+C 退出。

## 试用

1. Arduino 插到 PC 上，运行 `PcLinkServer.exe`。应显示 `COMn: PcLinkBridge 1, 1000000 baud`，然后是
   `Ready`。
2. 联机线一头插学习机，一头插 DB25 母座。在学习机上像以前一样装入 PCLINK。
3. 在学习机上输入 `c:`，再输入 `dir`。应列出文件夹里的文件，卷标为 `PCLINK`。再试试用 `type` 显示一个
   文本文件，用 `copy` 双向复制文件。

如果 `dir` 卡住，说明单片机在等联机线上的信号：检查接线和地线。如果服务端反复显示
`! ... starting over`，降低速度：把程序里的 `BAUD` 改成 115200 重新上传，服务端加 `--baud 115200`。

## 不用 Arduino：真正的并口

`PcLinkServer.exe --lpt` 在 PC 自己的并口上直接做握手，和 PCSVER 一样。联机线直接插在并口上。

- **并口**：主板上的并口（或主板插针加挡板），或 PCIe 并口卡。USB 转打印口线不能用。在 BIOS 里把并口
  模式设为 **SPP**（Normal、Standard）；ECP、EPP 模式下不能直接控制引脚。
- **驱动**：Windows 不允许普通程序直接操作并口引脚，所以要用 InpOut 驱动。从
  <https://www.highrez.co.uk/downloads/inpout32/> 下载，把 `inpoutx64.dll` 放在 `PcLinkServer.exe`
  旁边（32 位 Windows 用 `bin\x86\PcLinkServer.exe` 和 `inpout32.dll`）。**第一次要以管理员身份运行**，
  DLL 这时安装驱动。如果驱动仍然装不上，是 Windows 拒绝了它：关闭“内存完整性”（Windows 安全中心 >
  设备安全性 > 内核隔离详细信息），然后重启。
- **Windows 版本**：用 Visual Studio 2026 编译（在新电脑上运行 `build.bat`）的版本需要 Windows 8 或更新
  版本。Windows 7 请用 GitHub 上编译的版本：工作流 `.github/workflows/pclinkbridge.yml` 用 Visual Studio
  2022 编译，如果程序用到 Windows 7 没有的函数就报错。不支持 Windows XP。

然后：

    PcLinkServer.exe --list                 列出 Windows 识别的端口和地址
    PcLinkServer.exe [文件夹] --lpt         用 Windows 的第一个并口（没有则用 378）
    PcLinkServer.exe [文件夹] --lpt D010    用这个地址（十六进制）的并口，例如 PCIe 卡

启动时先检查并口（数据线必须能读回写入的值，否则会提示），再报告学习机那边线路的状态。联机线插在学习机上、
PCLINK 已装入时，应显示 `nibble F, handshake down (PCLINK idle)`。如果显示 `nibble F, handshake up`，
说明线路上没有信号：联机线或学习机没接上。然后在学习机上试 `c:` 和 `dir`，同上。

## 原理

一个字节分两个半字节传送，每个半字节双向握手，由学习机掌握节奏（PCLINK 的 $8282 和 $82A7，PCSVER 的
$02C2 和 $0377）。学习机拉高握手线，可能是“这是一个半字节”，也可能是“给我一个半字节”。只有服务端知道是
哪一种，所以单片机只按服务端的指示动作：服务端先送来要发的字节（`S`），再说要从学习机收几个字节
（`R`）；在此之前学习机一直等待，就像 PCSVER 读写磁盘时一样。单片机把收到的每个字节送回（`D`），每发出
64 个字节送回一个 `K`，所以服务端送去的数据不会超过单片机的缓冲区。细节见
`firmware/PcLinkBridge/bridge.h` 开头的注释。

如果有一方在请求中途停下超过 5 秒，服务端放弃这个请求，让单片机重新开始，已打开的文件和当前目录保持
不变。（这是为学习机复位或拔线准备的。如果学习机还停在那个请求里，双方会错位，需要重新装入 PCLINK。）
