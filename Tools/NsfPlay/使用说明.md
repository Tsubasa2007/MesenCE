# NsfPlay 使用说明

**NSFPLAY.CMD** 是步步高学习机（BBGDOS，BBK 1.0 或 BBK-98 BIOS）上的 NES 音乐播放程序，播放
`.NSF` 文件，用的是学习机 CPU 里的 2A03 声音通道。**nsf2bbk.py** 在 PC 上处理它不能直接播放的
NSF。

| 操作 | 键盘 | 手柄 1 |
| --- | --- | --- |
| 下一首 / 上一首 | 右 / 左（或 N / P） | 右 / 左 |
| 下一个 / 上一个文件 | 下、PgDn / 上、PgUp | 下 / 上 |
| 暂停 | 空格、回车 | Start、A |
| 退出到 DOS | Esc、Q | Select |

松开按键时才执行操作。屏幕显示文件名、NSF 文件头里的曲名、作者和版权，以及当前曲目和已播放的
时间。

## 使用

把 `NSFPLAY.CMD` 和音乐文件复制到 BBGDOS 软盘上，在 `A:\>` 提示符下输入 `nsfplay`。程序列出当前
目录里所有的 `.NSF` 和 `.NSB` 文件，从第一个开始播放；也可以在命令行上指定文件（`nsfplay mm2`、
`nsfplay cv3.nsb`）。英文系统和中文系统下都能用（运行时切换到英文屏幕，退出时切换回来），装没装
MOUSE.CMD、MUSIC.CMD 都可以。

哪些文件可以直接播放：

- **不切换存储体的 NSF**：可以。
- **存储体由文件头设好后不再改变的 NSF**（例如洛克人 2）：可以。程序会检查代码里有没有写存储体
  寄存器的指令，有就拒绝播放。
- **切换存储体或带扩展音源的 NSF**（VRC6、VRC7、MMC5、Namco 163、Sunsoft 5B）：先在 PC 上用
  `nsf2bbk.py` 处理，把生成的 `.NSB` 复制到软盘上。学习机没有这些音源芯片，扩展声部不发声，
  2A03 部分照常播放。
- **FDS** 音乐和装入地址低于 $8000 的音乐：不能播放。

音乐比 NTSC 制式的 NES 慢约 1%、低约 1%：学习机的 CPU 时钟是 Dendy 的 1.773 MHz，音高和定时
都由它决定。只支持 PAL 的音乐速度正确，但高约半音（学习机用 NTSC 的音高表）。选用帧计数器 5 步
模式的音乐会被改成 4 步模式（定时需要），包络和滑音可能稍快。

## nsf2bbk.py

    python nsf2bbk.py "Castlevania 3 (VRC6).nsf"          -> 同目录下的 CASTLEVA.NSB
    python nsf2bbk.py cv3.nsf -o CV3.NSB --seconds 120

需要 Python 3，不需要其他软件包。它在 6502 模拟器里运行每一首（INIT，然后 PLAY `--seconds`
秒，默认 60），并且：

- 把每条写存储体寄存器（$5FF8-$5FFF）的指令换成 `JSR`，调用 NSFPLAY 的存储体程序，由它映射
  对应的 8K 内存页；运行中没有执行到的这类指令也会按指令格式在代码里找出来（`--no-scan` 不找）；
- 把写扩展音源寄存器的指令（以及写 RAM 和 2A03 以外地址的指令）指向一块不用的内存，免得它们
  改写音乐数据或碰到学习机的 I/O 页；
- 列出音乐用到、但在文件里不相邻的 8K 存储体组合，NSFPLAY 装入时把它们复制到单独的页里；
- 最后按 NSFPLAY 的方式把每一首再运行一遍，检查写入的声音寄存器与原文件完全相同。所有曲目都
  相同才写出 `.NSB`。

如果某首曲子在 `--seconds` 秒之后才走到新的代码，可能遇到没有处理的指令；长曲子请加大
`--seconds`。`.NSB` 只给 NSFPLAY 用，其他 NSF 播放器不能播放。

## 编译

`NSFPLAY.CMD` 已经编译好放在这里。重新编译需要 [cc65](https://cc65.github.io/)（`ca65` 和
`ld65`），放在 PATH 里或用 `CC65` 指定：

    CC65="/d/Program Files/cc65/bin" sh build.sh

## 原理

- 文件读入空闲的 16K 内存页（`DosInquirePages`），按 4K 存储体顺序排放，所以第 *k* 个 8K 页正好
  是存储体 2*k* 和 2*k*+1。窗口显示这样一对存储体时直接映射这个页，其他组合用复制出来的页。
- 每首曲子播放时，程序接管整台机器：把 $0000-$07FF、$4E00-$57FF 和 $6000-$7FFF 保存到一个内存
  页，把常驻部分复制到 $5000（变量在 $4E00），关中断和 PPU 的 NMI，用 8K 页寄存器 $FF14、$FF1C、
  $FF24、$FF2C 把音乐映射到 $8000-$FFFF。音乐使用 2K RAM 和 $6000-$7FFF。BIOS 再次运行之前（换曲
  和退出时），这些全部恢复原样。
- PLAY 的定时靠查询 APU 帧计数器标志（$4015 第 6 位，4 步模式，在学习机上是 59.45 Hz）；50 Hz
  的音乐用场消隐标志，其他速度累计时间。如果帧计数器标志一直不出现（有的兼容机 APU 没有），
  程序改用场消隐定时。
- 键盘和手柄直接读（$4016/$4017）。手柄要读到两次结果相同：读手柄时如果遇上 DPCM 取样，手柄的
  数据会错一位。
- 时间和“Paused”在场消隐开始时直接写进 BIOS 的英文文字屏幕（名称表里就是字符码）。
- 接管之前，程序让 BIOS 关掉软驱马达（把 BIOS 的马达倒计时 $5FA0 设为 1），否则 BIOS 停止运行
  期间马达会一直转。

`nsf2bbk.py` 改出的调用使用固定地址：$5000 + 3*n*（`STA $5FF8+n`）、$5018（`STX`）、$5030
（`STY`）、$5048（`STA $5FF8+k,X`）、$5060（`STA $5FF8+k,Y`），以及 $5700-$57FF 这块空内存。
`nsfplay.s` 里有断言检查这个布局。

在 MesenCE 里用 BBK 1.0 和 BBK-98 BIOS 测试过：Journey to Silius、洛克人 2、恶魔城传说（VRC6，
处理成 `.NSB`）写入的声音寄存器与原 NSF 的参考运行逐条相同；换曲、换文件、暂停、退出键；装了
鼠标和音乐驱动的中文系统；退出后的 DOS。用 BBK 1.0 BIOS 还测试了切换存储体的恶魔城传说
（美版）、最终幻想 3、忍者龙剑传 3（都处理成 `.NSB`）：每个文件的第一首和最后两首都相同。没有在
真机上试过。
